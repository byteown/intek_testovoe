# Агент мониторинга пользовательской активности

Консольное приложение раз в 5 секунд делает дамп, какое окно находится в фокусе и была ли за это время активность пользователя, пакует накопленное в JSON и отправляет POST запрос на эндпоинт. Если сервер недоступен - данные не теряются: они складываются на диск и досылаются при восстановлении связи.

Кроссплатформенный: Windows (WinAPI) и Linux (X11).

---

## Требования

| | Windows | Linux |
|---|---|---|
| ОС | Windows 10 или новее | X11-окружение |
| Компилятор | C++17 (MSVC или MinGW-w64) | C++17 (GCC/Clang) |
| CMake | 3.14+ | 3.14+ |
| Библиотеки | — | `libx11-dev`, `libxss-dev` |

Для демонстрационного сервера нужен Python 3.

## Сборка

Зависимости скачиваются автоматически через CMake FetchContent

### Windows

```
cmake -S . -B build
cmake --build build --config Release
```

### Linux

```
sudo apt install build-essential cmake libx11-dev libxss-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

## Формат пакета

```json
{
  "agent_id": "DESKTOP-MIDDLE-C",
  "timestamp": 1792147320,
  "payload": [
    {
      "time": "2026-09-15 13:55:00",
      "process_name": "chrome.exe",
      "window_title": "ИНСАЙДЕР - Система мониторинга сотрудников",
      "user_active": true
    }
  ]
}
```

- `agent_id` — имя хоста
- `timestamp` — момент формирования пакета, unix-секунды
- `time` — момент снятия записи, локальное время
- `user_active` — были ли движения мыши или нажатия клавиш за последние 5 секунд

## Поведение при недоступности сервера

Неотправленный пакет сохраняется в `buffer.json` - в рабочем каталоге, из которого запущен агент. При следующей отправке содержимое буфера подмешивается к свежим записям (старые идут первыми) и уходит одним пакетом. После успешной доставки файл удаляется.

**Лимит.** В буфере хранится не более 100 записей. При переполнении вытесняются **самые старые**: для мониторинга свежие данные ценнее протухших.

**Атомарность записи.** Буфер пишется во временный файл и затем переименовывается поверх основного. Переименование в пределах файловой системы неделимо, поэтому при внезапном выключении на диске окажется либо целиком старая версия, либо целиком новая - но не обрезанный JSON.

## Конфигурация

Параметры заданы константами в `include/agent/config.h`:

| Константа | Значение | Смысл |
|---|---|---|
| `collect_interval` | 5 с | период снятия записи |
| `send_interval` | 30 с | период отправки |
| `collect_limit` | 10 | порог досрочной отправки |
| `buffer_limit` | 100 | максимум записей в буфере |
| `host`, `port` | `127.0.0.1:8080` | адрес сервера |
| `endpoint_path` | `/` | эндпоинт |
| `file_buffer_path` | `buffer.json` | файл буфера |
